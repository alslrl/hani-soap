# HaniSOAP 발표 구성 초안

작성일: 2026년 10월 9일 KST

예선 4분과 본선 10분 발표용 PDF의 구성 초안이다. 같은 환자 시나리오를 공유하고, 본선에서는 AI 처리·검증·개발 과정을 더 설명한다. 실제 구현 화면과 측정 결과가 확보되면 내용을 채운다.

## 1 발표에서 전달할 내용

진료 대화와 시술 기록이 의료진의 검토를 거쳐 환자 안내와 다음 재진으로 이어지는 과정을 보여준다. 환자가 말한 불편·질문·생활 제약이 이후 관리에서 어떻게 사용되는지 설명한다.

공식 심사 항목은 문제 정의와 필요성, AI 판단과 해결 방식, 작동하는 결과물, 검증과 개선, 사업성·도입 가능성, Codex 활용 과정이다. 아래 시간 배분은 팀 내부 제안이며 공식 배점이 아니다.

## 2 예선 4분

발표와 데모를 합해 4분이며 질의응답은 없다. 약 6장으로 구성하고 핵심 앱 화면을 중심으로 설명한다.

| 순서 | 내용 | 시간 | 보여줄 자료 |
| --- | --- | --- | --- |
| 1 | 사용자와 문제 | 35초 | 기록 오류와 후속 관리 누락의 구체적인 사례 |
| 2 | 환자 한 명의 사용 흐름 | 20초 | 진료 기록·안내·응답·다음 재진의 연결 |
| 3 | 진료 기록 화면 | 65초 | 녹음 또는 파일 업로드, 용어 후보·출처, 근거 연결 SOAP |
| 4 | 환자 안내와 다음 재진 | 50초 | 승인 안내, 불편 응답, 연락 필요, 다음 브리핑 |
| 5 | 검증 결과와 Codex 활용 | 45초 | 실제 비교 결과와 개발·수정 사례 하나 |
| 6 | 도입 가치와 남은 과제 | 25초 | 사용할 사람, 확인한 가치, 구현·모의 처리 범위 |

총 240초다. AI 모델 이름은 해당 화면에서 필요한 만큼만 설명한다. Codex 활용은 검증 슬라이드 안에서 약 20~30초로 소개한다.

## 3 본선 10분

공식 10분에는 발표·데모·질의응답이 포함된다. 기본안은 발표 7분과 질의응답 3분이며 현장 안내에 따라 조정한다. 예선의 핵심 흐름을 유지하고 설명을 확장한다.

| 순서 | 내용 | 시간 | 예선보다 추가할 설명 |
| --- | --- | --- | --- |
| 1 | 사용자와 문제 | 50초 | 현장 자료의 근거와 확인 범위 |
| 2 | 전체 사용 흐름 | 30초 | 의료진·직원·환자의 역할 |
| 3 | 진료 기록과 시술 입력 | 100초 | PC 단일 수음, 전체 녹음·실시간 처리, 구현된 아이패드 입력 |
| 4 | 안내·응답·재진 연결 | 70초 | 환자의 상황에 따라 달라지는 안내와 확인 사항 |
| 5 | AI 처리와 차별점 | 60초 | 화자 분리, 사전·출처 기반 보정, 근거 연결과 의료진 검토 |
| 6 | 검증과 개선 | 50초 | 오류·오교정·검토 시간, 발견한 실패와 수정 결과 |
| 7 | Codex 활용 과정 | 40초 | 실제 작업 지시, 사람의 검토, 수정·통합·검증 사례 |
| 8 | 도입 가치와 다음 단계 | 20초 | 운영 방식, 비용·시간 지표, 남은 검증 |
| 9 | 질의응답 | 180초 | 필요한 경우 근거·검증 자료를 추가로 제시 |

발표 420초와 질의응답 180초로 총 600초다. 질문 대비용으로 기능별 모델 표, 상세 검증 결과, 실제·모의 구현 범위, 데이터 출처를 준비한다.

## 4 Codex 활용법

Codex에 준 맥락, 작업 지시, 사람이 검토한 내용, 확인한 결과를 짧게 설명한다. 실제로 사용한 방법과 확보한 증거만 발표에 넣는다.

| 활용법 | HaniSOAP에서 설명할 내용 | 보여줄 증거 |
| --- | --- | --- |
| 프로젝트 자료를 맥락으로 제공 | 기획서·용어 사전·한자·출처·시그마차트 화면을 참고해 계획과 입력 구조 정리 | 자료와 계획의 일부 |
| 기능과 완료 조건 지정 | 파일 업로드처럼 범위가 분명한 작업과 실제 동작 확인 조건을 함께 전달 | 작업 지시 한 줄과 완성 화면 |
| 반례 테스트와 수정 | 아침·기침·침대 오탐, 약침 중복, 과거·현재 NRS 혼동 등의 사례 검사 | 실패·수정 전후 테스트 결과 |
| 도메인 검토 반영 | 연화가 확인한 용어·혈자리·문안 의견을 다음 수정에 반영 | 검토 의견과 반영 전후 결과 |

작업 지시 예시:

> 현재 전사문에서 시술 종류를 감지하는 기능을 구현해. 아침·기침·침대는 침으로 잡으면 안 되고, 약침도 침과 중복되면 안 돼. 이 사례들을 테스트하고 수정 전후 결과를 보여줘.

예선에서는 실제 사례 하나를 작업 지시·발견한 문제·수정·검증 결과로 압축한다. 본선에서는 검증 슬라이드와 연결해 설명한다. Skills, MCP, AGENTS.md 등은 실제 사용한 작업과 결과를 연결할 수 있을 때만 구체적인 방법으로 소개한다.

현재 자료로 설명할 수 있는 사례는 자료 기반 계획 작성, 용어 사전 품질 검사, UI 참고 자료 조사다. 기능 구현·오탐 수정·기기 동기화 검증은 완료 후 증거를 확보해 추가한다. 아직 계획인 작업을 완료한 성과로 적지 않는다.

## 5 개발 중 모을 발표 자료

- 핵심 흐름의 실제 앱 화면. PDF에서는 입력·검토·결과의 상태 변화를 순서대로 보여준다.
- 같은 음성의 최초 전사와 사전·LLM 보정 결과, 오교정 사례, 검토 시간.
- Codex 작업 요청, 처음 발견한 문제, 수정 내용, 검증 결과와 해당 커밋.
- 연화의 도메인 검토 의견과 반영한 내용.
- 실제 동작, 모의 응답·전송, 아직 검증하지 않은 기능의 구분.

가상 NRS 변화는 경과 표시 기능의 예시로 사용한다. 치료 효과나 실제 사용자 성과로 설명하지 않는다. 기존 자료·외부 자산과 당일 새로 구현·개선한 부분도 구분한다.
