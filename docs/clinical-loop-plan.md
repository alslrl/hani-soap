# 진료 분석·다중 입력 SOAP·맞춤 케어 구현 계획

2026-10-09. 기존 녹음·화자 역할·사전 검토·SOAP·iPad·카카오 흐름과 식별정보 가림을 보존하면서 세 연결을 구현한다. 실물 iPad/Pencil/마이크 검증은 사용자가 다른 작업에서 진행 중이다. 대본·TTS 리허설 제작은 이 구현에서 실행하지 않는다.

## 1. 진료 분석 후보

현재 방문의 최신 전사를 대상으로 `gpt-6.1-sol / medium` Structured Output을 호출한다. 재진 12항목 답변, 오늘 NRS/횟수 등 측정 후보, 직접 표현한 걱정·효과 의문·이해 부족·실천 어려움을 추출한다. 각 후보는 원래 구간 ID·정확한 인용·시점을 보존한다. 질문·과거 수치·계획을 오늘 답변/측정으로 저장하지 않는다. 근거가 없으면 미확인으로 둔다.

후보는 `jobs.kind=analysis`, `result.task=clinical_analysis`에 저장하며 기존 briefing 작업과 구분한다. 답변이 있는 항목은 원문 인용과 함께 화면에 미확인 AI 초안으로 채운다. 답변이 없는 항목은 빈칸으로 유지하고 저장된 의료진 입력과 작성 중인 입력을 덮어쓰지 않는다. 초안을 저장해도 검토 전 상태를 유지하며 SOAP 입력에서는 제외한다. 통증 NRS는 기존 통증 입력칸 한 곳에서 검토·저장하고 재진 질문에서는 현재 값과 이동 버튼을 제공한다. 검토 전 값은 확인된 관찰·연락 작업에 자동 반영하지 않는다. 의료진이 후보를 확인하면 기존 followup_answers/observations에 근거와 함께 반영한다. 수정한 값은 수기 출처를 추가한다. 중복 확인은 같은 항목을 중복 생성하지 않으며 새로운 전사가 생기면 이전 분석은 확인 대상으로 사용하지 않는다.

환자 표현은 확인된 `reviewed_signals`로 같은 작업에 보관한다. 원문 구간과 검토 시각이 연결되며, 숨은 감정·이탈 확률·치료 필요성을 추정하지 않는다. 재분석·후보 저장은 PIN과 Origin 및 환자·방문·전사 버전을 검증한다.

## 2. 다중 입력 SOAP

생성 입력은 전사에 더해 같은 방문의 시행 확인된 시술, 현재 필기 버전과 연결된 자동 추출 텍스트(판독 확인 전 표시) 및 검토한 필기 텍스트, 확인된 재진 답변/측정을 수집한다. 미확인 시술 후보와 출처 버전이 맞지 않는 필기 추출문은 제외한다. 현재 버전의 자동 추출문은 SOAP 초안 입력에 포함하며 최종 승인은 의료진이 한다. 시술은 P, 압통 관찰은 적합한 O 근거, 환자 보고는 S로 구분하고 계획과 시행을 혼합하지 않는다. 약침 약제·용량과 유침시간은 현재 제외 범위를 유지한다.

추가 입력은 결정적으로 렌더링한 원문과 실제 기록 ID를 제공한다. 모델의 정확한 인용과 허용 섹션을 서버에서 검증한다. 근거 ID는 기존 evidence.segment_id 필드를 호환해서 사용하지만 저장 source_refs는 전사/수기 출처를 구분한다.

SOAP에는 입력 해시·원문 전사 버전·포함한 기록 ID/버전의 스냅샷을 저장한다. 추가 시술/필기/답변이 바뀌면 생성 작업을 재사용하지 않고, 생성 중 입력 변경은 stale로 표시한다. 승인 단계에서도 최신 입력과 대조한다. 기존 원문·승인 SOAP는 수정하지 않으며 갱신은 새 초안으로 저장한다.

## 3. 환자 맥락 맞춤 케어

기준 방문의 승인 SOAP 계획을 행동 안내의 근거로 유지한다. 같은 환자의 실제/모의 출처가 표시된 지난 응답, 미해결 연락, 검토한 직접 표현, 확인된 재진 답변/경과를 날짜와 함께 전달한다. 환자/보호자와 안내 시점도 반영한다.

안내 방향과 문장별 근거를 제시하고, 지난 응답을 현재 상태·해결 완료·약의 인과관계로 강화하지 않는다. 확인/설명 문장은 해당 맥락 근거를 인용할 수 있지만 새 치료·용법·진단은 만들지 않는다. 생성 중 입력 변경은 검토 필요로 표시한다. 문안의 최종 승인은 의료진이 하고 카카오 발송은 approved_body를 그대로 사용한다.

## 공통 계약과 역할

- 진료 분석 결과는 jobs.result에 저장한다. 검토한 직접 표현의 공통 계약과 조회는 `src/lib/ai/clinical-analysis-context.ts`로 공유한다.
- SOAP 입력 스냅샷은 기존 visit_documents JSONB payload의 선택 필드로 추가한다. 새 임상 테이블이나 기존 데이터 재주입은 필요하지 않다.
- 공통 계획/계약과 SOAP 연결은 부모가 담당하고, 진료 분석 및 맞춤 케어는 별도 관리 checkout에서 병렬 진행한다. 각 작업은 API/저장/근거 검증과 UI를 함께 준비하고 부모가 통합한다.
- 기존 AiTextPrivacy를 모든 새 텍스트 호출에 적용한다. 대응표나 식별정보 원문을 로그·브라우저 결과에 저장하지 않는다.

## 검증과 완료 기준

1. NRS 0, 과거/현재 수치, 야뇨 횟수, 미응답 질문, 보호자 보고, 직접 걱정 표현을 합성 전사로 검증한다.
2. 후보 확인·수정·중복·새 전사 충돌, 원문 및 승인 기록 보존을 저장소/API에서 검증한다.
3. 시행/미시행·검토/미검토 필기, 입력 변경과 재생성/승인 차단, 다중 출처 인용을 검증한다.
4. 지난 불편 응답과 현재 호전의 구분, 미해결 연락 유지, 보호자 수신, 맞춤 문장 근거와 승인 문안 불변을 검증한다.
5. 클린 checkout에서 타입·관련 단위/서버·격리 PostgreSQL·브라우저 흐름·production build를 확인한다. 실제 모델 검증은 소수의 합성 데이터로 수행한다.
6. 통합 코드 커밋/푸시/배포 후 PIN/API와 저장 상태를 확인한다. 사용자에게 새로운 카카오 메시지는 추가 승인 없이 보내지 않는다.

API 참고: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol).
