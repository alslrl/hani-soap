# 확인된 환자 맥락을 반영하는 케어

2026-10-09. 맞춤 안내 생성과 검토 화면의 구현 계약. 실제 카카오 발송과 cloud 임상 데이터 변경은 이 작업의 검증에 포함하지 않는다.

같은 승인 계획이라도 환자가 직접 말한 걱정, 치료 효과에 대한 질문, 설명에서 이해하지 못한 부분, 복용 실천의 어려움이 다르면 안내에서 먼저 확인할 내용이 달라진다. 모델은 이 소통 방향과 문장을 제안하고, 의료진이 날짜와 원문을 대조해 최종 문안을 편집·승인한다.

## 입력과 근거

`src/lib/ai/care-context.ts`의 `collectCareInputs`가 입력을 모은다. 같은 기관·환자에서 기준 방문까지의 기록만 사용하며, 생성 시각보다 나중의 응답·측정·검토는 제외한다. 후속 안내에서 응답일이 원래 진료일보다 늦을 수 있으므로, 이미 받은 응답은 원래 날짜와 함께 지난 보고로 넣는다.

- 기준 방문의 최신 승인 SOAP P는 행동·생활관리 안내의 근거다.
- 명시적으로 선택한 복약 과정은 처방명·복용 횟수·기록된 안내와 승인 근거 방문이 확인된 경우에만 복약 안내 근거로 노출한다. 종료된 과정이나 미확인 용법을 새 지시로 옮기지 않는다.
- 지난 발송 문안과 응답은 실제 발송 채널·모의 응답 출처·날짜를 구분한다. 응답은 환자 보고이며 현재 상태나 약의 인과관계를 확정하지 않는다.
- 열린 연락 작업은 미해결로 유지한다. 이후 긍정 응답이 와도 모델이나 입력 수집기가 연락을 닫지 않는다.
- 재진 답변은 검토·확인·해당 여부가 명시된 기록만, 측정은 검토된 기록만 사용한다. NRS와 횟수·활동 척도를 구분한다.
- 직접 표현은 공통 `reviewedPatientSignals`를 통해 최신 전사에 근거를 둔 의료진 확인 결과만 사용한다. 미검토 분석 후보는 넣지 않는다.
- 과거 승인 기록은 날짜가 붙은 과거 맥락이다. 오늘의 증상·수치·시술 시행 사실로 복사하지 않는다.

각 근거는 안정된 `source_id`, 원래 `record_id`, `visit_id`, 날짜, 정확히 인용할 `text`, 허용 용도, 출처와 원문 `source_refs`를 갖는다. 모델에는 새 식별정보 필드를 더하지 않으며, 전달하는 모든 텍스트는 기존 `AiTextPrivacy`를 거친다. 결과를 복원한 후 실제 원문과 대조한다. 가림 대응표는 요청 중 서버 메모리에만 두고 저장하는 감사 정보는 수량·범주뿐이다.

## 생성과 검토

`generateCareStep`은 기존 `gpt-6.1-sol / low`와 Structured Output을 유지한다. 결과에 안내 방향의 제목·이유·근거, 문장별 용도·정확한 인용을 추가한다.

문장의 용도는 행동 안내, 승인 내용 설명, 지난 보고 인정, 현재 상태를 묻는 질문으로 구분한다. 행동과 임상 설명은 승인 계획이나 선택한 확인된 복약 기록에 근거해야 한다. 맥락 근거에서는 확인·설명 질문을 만들 수 있지만 새로운 약·용법·용량·진단·운동 처방을 만들 수 없다. 직접 걱정이나 효과 의문은 해당 의료진 확인 표현이 있어야 안내 방향으로 선택할 수 있다. 숨은 감정이나 이탈 확률을 추정하지 않는다.

서버는 근거 ID와 정확한 인용, 새 수치, 근거별 허용 용도, 과거/현재 구분, 해결 완료·약의 인과관계로의 강화를 검사한다. 이는 임상 타당성의 자동 승인과 다르며 최종 문안은 항상 의료진이 검토한다.

케어 화면에는 수신자가 환자/보호자인지, 안내 시점, 제안한 방향과 이유, 날짜·원문 근거를 표시한다. 문장별 근거에는 원래 전사·기록의 인용도 확인할 수 있다. 초안은 계속 편집할 수 있고 재생성은 새 초안으로 저장한다. 카카오 전송 단계는 기존 `approved_body`를 사용하며 다시 생성하지 않는다.

## 변경 감지와 승인 훅

공개 계약은 다음과 같다.

```ts
collectCareInputs(state, { visitId, stage, medicationCourseId?, asOf })
fingerprintCareInputs(snapshot): string
assertCurrentCareMessage(state, messageId, asOf = now): void
```

입력 스냅샷은 `jobs.result`의 아래 필드에 저장한다. 기존 `care_messages`나 SQL 테이블 변경은 필요하지 않다.

- `care_context_version`: `contextual-care-v1`
- `care_input_as_of`, `care_input_snapshot`, `care_input_hash`
- `care_strategy`: 수신자·시점과 방향별 제목·이유·날짜가 붙은 근거
- `evidence`: 기존 `text/quote/source_soap_id/section`을 유지하면서 새 맥락 ID·용도·날짜·출처를 추가
- 기존 `missing_information`, `review_notes`, `stale_input`, `text_privacy` 유지

단순히 시간이 흘렀다는 이유로 입력 해시가 바뀌지 않는다. 새 응답·연락 처리·확인된 표현·답변·측정·승인 계획의 변화는 입력 해시에 반영한다. 작업 대기 중 입력이 바뀌면 생성하지 않고, 복약 안내 일정도 입력 스냅샷의 확인된 기준일로 고정한다. 생성 중 바뀌면 초안을 보존하되 `stale_input`을 표시한다.

부모의 `care.approve` 처리는 `approved_body`를 고정하기 직전에 `assertCurrentCareMessage`를 호출한다. 이때 현재 시각까지의 새 응답도 수집해 비교한다. 입력이 다르면 `CARE_INPUT_STALE` 409로 승인을 막고 최신 맥락으로 재생성하도록 안내한다. 기존 seed·수기 문안·구형 AI 작업은 호환되며 이미 승인한 문안은 변경하거나 재생성하지 않는다.

## 검증

새 테스트는 같은 승인 계획에서 속 불편과 복용 실천 어려움의 구분, 보호자 수신, 다른 환자·미래 기록 배제, 최신 전사의 확인된 직접 표현, 과거 수치와 오늘 미확인 값의 구분, 긍정 응답 이후 열린 연락 보존을 확인한다. 생성 결과의 정확한 인용·수치·근거 용도, 개인정보 가림과 인용 복원, 생성 중 입력 변경과 승인 차단도 검사한다.

모델 사용 기준은 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)와 [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)의 현재 문서를 확인했다. 실제 모델 검증은 별도의 로컬 저장소에 만든 합성 사례 소수로 수행한다.
