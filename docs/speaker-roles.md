# 전사 화자 역할

전체 녹음/업로드의 화자 분리 전사가 끝나면 기존 교정 모델 설정(`OPENAI_MODEL_CORRECTION`, 기본 `gpt-6.1-sol`)으로 전체 대화를 한 번 읽어 그룹별 의료진/환자/보호자/미확인 역할을 추론한다. 순서·성별·A/B/C 문자만으로 정하지 않으며, 해당 그룹의 정확한 원문 인용 근거가 없으면 미확인으로 남긴다. 역할 추론 실패는 전사를 실패시키지 않으며 UI에 수동 검토 안내를 남긴다. 추론된 역할은 별도 확인 절차 없이 첫 SOAP 초안 입력에 포함된다.

`Segment.raw_speaker`는 제공자가 반환한 원래 그룹 문자열이다. `source_segment_id`는 최초 구간 ID이며 검토 저장으로 `id`가 바뀌어도 유지된다. `Transcript.speaker_roles`는 그룹별 역할과 `inferred`/`human` 출처를 저장한다. 기존 데이터는 필드가 없어도 유효하며, 오래된 작업의 `result.rawSpeakers`는 검토 시 호환해서 읽는다. Supabase는 기존 transcript JSONB payload에 메타데이터를 저장하므로 SQL 스키마 변경이나 마이그레이션이 필요 없다. JSON Schema에 선택 필드만 추가한다.

역할 우선순위는 개별 `speaker_override` → 그룹 `speaker_roles` → 기존 `speaker`다. 그룹 수정은 그 그룹의 모든 발화에 적용하되 개별 수정은 유지한다. UI의 ‘그룹 역할로 되돌리기’는 override를 제거한다. API `speakerGroups`는 원래 그룹 이름을 키로 쓰고, `speakers`는 현재/최초 구간 ID를 키로 쓰며 `null`은 개별 수정 해제를 뜻한다. 알려지지 않은 그룹·구간·역할을 거부한다.

검토는 원문이나 이전 버전을 수정하지 않고 새 전사 revision을 추가한다. 역할 수정과 검토 전사는 새 revision으로 SOAP를 다시 생성한다. 용어 재검사와 이후 SOAP 생성은 저장된 사람의 선택을 보존하며 역할을 다시 추론하지 않는다. 승인 SOAP와 원문·원래 화자·타임스탬프는 기존 불변성 검사로 보존한다. 전체 전사를 자유롭게 다시 쓰면 구간 위치와 화자 연결을 보장할 수 없어 새 단일 미확인 구간으로 저장한다. 이미 저장된 자유 편집 전사를 내용 변경 없이 다시 저장할 때는 해당 revision의 구간 역할을 유지한다.

검증: 역할/근거 및 우선순위 단위 테스트, 격리된 로컬 저장소에서 다회 revision·재검사·원문/SOAP 보존 테스트, 추론 실패와 최신 reviewed revision을 사용하는 SOAP pipeline 테스트, 브라우저 그룹/개별 수정과 검토 저장→SOAP 요청 테스트. 실제 모델 검증은 합성 대화만 사용하며 임상 데이터에 호출하지 않는다.
