# 데모 환자 사진과 프로필 준비

작성일: 2026년 10월 9일 KST

데모용 가상 인물의 증명사진 스타일 이미지 2장을 생성해 프로젝트에 저장했다. 저장 스키마 v1 확정 후 두 환자의 seed를 생성했고 사진을 해당 가상 patient ID와 연결했다. 실제 DB 주입과 앱 화면 연결은 구현 단계에서 진행한다. 사진만으로 임상 정보나 환자 속성을 추론해 채우지 않는다.

## 준비한 사진

| 자산 | 용도 | 프로젝트 파일 |
| --- | --- | --- |
| `demo-adult-01` | 성인 환자 시나리오용 가상 사진 | `public/demo/portraits/demo-adult-01.png` |
| `demo-child-01` | 소아 환자 시나리오용 가상 사진 | `public/demo/portraits/demo-child-01.png` |

두 사진은 정면 상반신, 연회색 배경, 자연스러운 표정의 3:4 세로 구도로 만들었다. 원본 크기는 각각 1086×1448이다. 환자 목록의 작은 프로필과 상세 화면에 같은 자산을 사용하며, 표시 크기와 원형·사각형 처리는 UI에서 조정한다. 그림을 생성한 원본은 별도로 남겨 두었다.

생성에는 기본 내장 `image_gen` 도구를 사용했다. 실제 환자나 기존 인물 사진을 참고 이미지로 사용하지 않았다. 이미지 파일은 준비됐지만 아직 환자 DB나 앱 화면에 연결한 상태는 아니다.

## 프롬프트와 생성 기록

[생성 기록과 전체 프롬프트](../data/demo/portrait-assets.json)에 자산 ID, 파일·공개 경로, 크기, SHA-256, 사용한 프롬프트를 보관했다. `profile_binding`에는 검증한 seed의 가상 patient ID를 연결했다.

공통 프롬프트 방향은 가상의 한국인, 정면 상반신, 증명사진 스타일, 자연스러운 피부·표정, 연회색 스튜디오 배경, 3:4 세로 구도, 글자·워터마크 없음이다. 성인 사진은 20대 중반 여성, 소아 사진은 약 6세 아동의 시각적 예시로 요청했다. 이 설명은 사진 생성 조건이며 확정된 환자 프로필 데이터가 아니다.

## 확정 스키마로 생성한 환자 데이터

사용자 요청에 따라 저장 형식 v1을 확정한 뒤 서브 에이전트로 [두 환자의 seed](../data/demo/patients.seed.json)를 생성했다. 환자 2명·방문 6건·SOAP 4건·질문 답변 76행·안내 6건·응답 3건·연락 작업 1건을 준비했다. 오늘 두 방문은 대기이며 답변과 오늘 측정값은 빈 상태다. 실제 API·DB·발송 결과로 취급하지 않는다.

1. 확정한 DB·입력 검증 스키마, 시나리오, 필요한 환자 수와 자산 목록을 전달한다.
2. 가상 이름·인적 정보·방문·진료·VAS·안내·응답을 스키마에 맞게 만들고 관계와 시간 순서를 검증한다.
3. 기존 진료 대화의 사실과 별도로 구성한 가상 이력을 구분한다. 기존 전사에 나온 참여자의 실명·생년월일을 그대로 환자 프로필에 넣지 않는다.
4. 실제 연락처를 임의로 만들지 않고, 데모의 연락 정보와 카카오 본인 발송 연결을 구분한다.
5. 인물의 연령대·표현과 맞는 사진 자산을 연결하고 필요한 추가 사진은 같은 형식으로 생성한다.
6. 스키마 검증을 통과한 데이터만 seed 파일에 저장한다. 데모 초기화·재실행에서 ID·연결·중복 처리 결과가 일관되게 유지되도록 한다.

환자 목록과 상세 화면에는 가상 데모 데이터임을 표시한다. 스키마·관계·시간·질문·측정·승인·연락 상태·사진 해시와 30개 메모리 내 경계·오류 변형 검사를 통과했다. 검증 명령은 아래와 같다.

```sh
python -m venv /tmp/hani-demo-validation
/tmp/hani-demo-validation/bin/pip install -r scripts/requirements-demo.txt
/tmp/hani-demo-validation/bin/python scripts/validate_demo_data.py --self-test
```
