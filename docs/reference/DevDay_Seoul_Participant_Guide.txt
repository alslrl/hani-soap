      02 / BUILD RULES




만들기 전에
사전 작업을 공개하고, 행사 당일의 개발 과정을 확인할 수 있게 남겨 주세요.




Only Codex
개발에 사용하는 AI 코딩 도구는 Codex만 허용됩니다.
일반 IDE·편집기, 터미널, 컴파일러, 패키지, 데이터베이스, Git·GitHub, 클라우드, 빌드·테스트·배포 도구는 사용할
수 있습니다. 해당 도구에 포함된 다른 AI 코딩 보조 기능은 사용하면 안 됩니다.



다른 AI 코딩 도구 사용이 확인되면 참가 무효 처리됩니다. 계정 공유, 대리 개발, 팀 외 인력의 코드 작성 역시 참가 무효 또는 심
사 제외 사유가 될 수 있습니다.




빈 저장소부터, 이력은 그대로
  새 GitHub 저장소 등록
  행사 시작 시 코드와 기존 커밋 이력이 없는 빈 저장소를 등록합니다. 기본 브랜치는 main으로 설정합니다.

  사전 작업은 명확히 구분
  사전 준비한 코드·자료·기존 프로젝트는 사용할 수 있습니다. 가져온 부분과 당일 새로 구현·개선한 부분을 제출 자료
  에 구분해 주세요.

  기록과 출처 유지
  등록한 저장소를 계속 사용하고 커밋 이력을 삭제하거나 재작성하지 마세요. 외부 라이브러리·템플릿·데이터셋·모델의
  출처와 활용 범위를 밝혀 주세요.




하드웨어 팀도 참여할 수 있습니다
라즈베리파이·아두이노·로봇팔 등 디바이스와 전원·케이블·제어 보드는 직접 준비합니다. 전원·네트워크·설치 공간·동작
범위에 별도 요구사항이 있으면 사전에 알려 주세요.

      03 / SUBMISSION




제출은 17:00 전에
팀별 6자리 키로 접속합니다. 플랫폼에 표시된 팀명을 먼저 확인해 주세요.



최종 제출물은 네 가지
01    GitHub 저장소 URL
      AWS 세션 후 먼저 등록 · 기본 브랜치 main · 운영진 열람 권한 확인


02    발표용 PDF
      운영진이 1차 발표에 그대로 사용 · 로컬 사본도 보관


03    데모·참고 링크
      운영진이 바로 열 수 있도록 설정 · 네트워크 장애 대비 녹화 데모 준비


04    Codex 기록 ZIP
      팀원별 로그를 함께 압축 · 비밀 키·개인정보·회사 기밀 포함 여부 점검



접속 정보와 로그 안내 플랫폼 주소, 로그 내보내기 방법, 파일 제한은 팀장에게 전달되는 제출 안내를 확인해 주세요. Private
저장소는 별도 안내되는 운영진 GitHub 계정에 열람 권한을 부여해야 합니다.




 17:00 KST                     플랫폼 제출 완료 + main 최종 반영
                               두 조건을 모두 충족해야 합니다.



16:58 main에 push 또는 PR merge                  인정

16:55 feature 브랜치에만 push                      평가 대상 main에 없어 불인정

16:50 commit → 17:02 push                     마감 이후 반영으로 불인정

기본 브랜치가 master인 상태                            main으로 변경하고 마감 전에 반영



참가자 PC의 commit 시각이 아닌 GitHub 서버의 main 최종 push 상태를 기준으로 합니다. 플랫폼 종료 후 URL·파일 등록
과 교체, 지각 제출은 허용되지 않습니다.


17:00–17:10은 운영진 점검 시간입니다. 파일을 다시 제출하면 최종 제출 시각이 갱신될 수 있으므로 여유 있게 완료해 주세요.
