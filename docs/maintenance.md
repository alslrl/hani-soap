# 유지관리 계획

작성일: 2026-10-21. 아래는 공개 준비를 위한 실행 순서와 완료 기준입니다. 사용자 수·임상 효과·출시일을 확정하거나 정기 자동 실행을 설정한 계획은 아닙니다.

## 1. 공개 안전성과 권리 정리

- Codex 로그, 진료 원음·전사, 노션 원본, 발표 PDF, 대회 안내와 외부 제품 스크린샷을 현재 공개 파일에서 제외합니다.
- 과거 커밋과 다른 원격 브랜치에 남은 사본을 목록화합니다. 이력 재작성은 백업·협업 영향·원격 갱신 범위를 확인하고 소유자 승인 뒤 수행합니다.
- 남성형 도해의 구성 요소, 경혈 설명, 변증명·처방명 원자료, 합성 시나리오의 원문 범위를 검토합니다. 권리가 불명확하면 대체·제거·선택 설치 방식 중 하나를 결정합니다.
- 완료 기준: 공개 대상·라이선스·출처·제외 목록이 일치하고, 이력과 외부 자산의 미해결 항목을 숨기지 않습니다. 현재 트리의 파일 삭제만으로 이 단계 전체를 완료 처리하지 않습니다.

## 2. 재현 가능한 개발 환경

- 새 환경에서 설치·수동 차팅·가상 데이터 초기화를 확인합니다.
- 키가 없는 경우와 유료 AI가 연결된 경우를 문서와 화면에서 구분합니다.
- 공개 파일 검사·타입 검사·단위 검사·서버 검사를 우선 자동화합니다. DB·E2E·빌드는 격리 환경에서 별도 확인합니다.
- 완료 기준: 각 검사 명령과 실제 결과·미검증 항목을 남기고, 새로운 개발자가 운영 자격증명 없이 기본 기능을 시험할 수 있습니다.

## 3. 진료 기록의 신뢰성과 보안

- 입력 변경 후 오래된 SOAP 승인, 원문 근거 누락, 의료진 확인 상태, 환자·방문 경계의 회귀 검사를 유지합니다.
- 인증·기관별 접근·요청 상한·동시 수정·발송 중복을 점검합니다.
- 실환자 도입 전에는 동의·최소 수집·보존 및 삭제·감사 기록·계정별 권한·임상 검증을 별도로 설계하고 검토합니다.
- 완료 기준: 모델 출력이 자동으로 확정 기록이나 환자 발송으로 바뀌지 않으며, 실제 확인하지 않은 기기·외부 연결을 검증 완료로 표시하지 않습니다.

## 4. 기여와 릴리스 운영

- 이슈는 버그·개선·보안·권리 확인으로 분류하고 재현 자료의 개인정보를 먼저 확인합니다.
- PR은 변경 목적·테스트·라이선스·데이터 영향·롤백 방법을 검토한 뒤 병합합니다.
- 권리·보안 차단 항목을 해소한 후 태그와 변경 기록을 갖춘 첫 공개 릴리스를 준비합니다.
- 정기 점검에서는 새 이슈, 의존성 보안 업데이트, 테스트 실패, 외부 자료 조건 변경을 확인합니다. 아직 자동 루틴이나 응답 SLA는 설정하지 않았습니다.

## Codex 활용 계획

Codex는 이슈 재현, 작은 수정과 회귀 테스트, PR 검토 보조, 의존성 갱신, 릴리스 체크리스트·기술 문서 관리에 활용합니다. 유지관리자가 결과와 권한을 검토한 뒤 병합·배포합니다. 지원 프로그램의 크레딧 용도는 이런 오픈소스 유지관리 작업을 중심으로 설명하며, 진료 전사 서비스 운영비와 혼동하지 않습니다.
