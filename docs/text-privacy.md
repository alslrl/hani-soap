# AI 전송용 텍스트의 식별정보 1차 가림

2026-10-09 구현. 이 기능은 후속 텍스트 AI 요청에 전달하는 사본에서 정해진 식별정보를 줄인다. 원음 비식별화, 완전 익명화, 무보관 또는 실환자 서비스의 법적 요건 충족을 의미하지 않는다.

## 처리 대상

- 해당 방문 차트에 등록된 환자 이름과 보호자 이름. 정확한 이름·일부 호칭/조사와 이름 사이 공백을 대조한다. 일반 임상 단어와 겹칠 수 있는 두 글자 이름은 님/씨 호칭이 있을 때만 처리한다.
- 숫자로 적힌 일반적인 국내 휴대전화·지역 전화·070 번호 및 +82 표기.
- 일반적인 ASCII 이메일 주소.
- 생년월일 부분이 유효한 주민번호 형태의 13자리 숫자. 실제 주민번호인지 조회하거나 확정하지 않는다.

자유롭게 등장한 다른 사람 이름·기관명·주소, 한글로 읽은 전화번호, 지원하지 않는 형식·전사 오인식은 놓칠 수 있다. 탐지된 수가 0이라는 사실은 개인정보가 없다는 뜻이 아니다.

통증 NRS, 약 용량, 복용 횟수, 좌우, 측정값, 진료 날짜와 나이는 이 1차 가림 대상이 아니다. 예: `우측 45cm, 좌측 43cm, NRS 8, 하루 3회 식후 30분, 2주 뒤 내원`은 그대로 유지한다. 임상적으로 중요한 숫자를 일괄 삭제하지 않는다.

## 데이터 흐름

1. 현재 방식대로 음성을 OpenAI에 보내 전사한다. **이 최초 음성 전송에는 본 기능의 가림 처리가 적용되지 않는다.**
2. 화자 역할 추정·사전 용어 검토·SOAP·환자 안내·과거 기록 브리핑을 요청하기 전에, 서버에서 원본을 복사하고 식별정보를 요청별 보호 표식으로 치환한다.
3. 복원 대응표는 해당 요청을 처리하는 서버 메모리에만 둔다. 모델 입력이나 작업 결과에 대응표·원래 식별정보 목록을 추가하지 않는다.
4. 모델이 반환한 표식을 서버에서 복원한 뒤 원문 인용·화자 근거·수치를 기존 검증기로 확인한다. 모르는 표식은 거절한다. 교정 후보의 원문 offset은 서버에서 유지하며, 가림 때문에 길이가 달라진 입력에는 원문 offset을 보내지 않는다.
5. 검토용 최초 전사, 기존 승인 SOAP와 안내문은 보존한다. 이후 AI 요청도 다시 가린 사본을 생성한다. 본 기능은 앱의 원본 기록을 익명 데이터로 바꾸지 않는다.

`src/lib/privacy/text.ts`의 `AiTextPrivacy`를 사용한다. 새 텍스트 AI 기능을 추가할 때에도 방문의 환자 정보를 제공하고, 입력에는 `privacy.mask()`, 반환값에는 원문 검증 전에 `privacy.restore()`를 적용한다. 환자 문맥이 없으면 임의로 다른 환자 이름을 사용하지 않고 요청을 중단한다.

## 파일명과 화면 표시

새 음성 업로드는 브라우저 요청 전에 파일명 본문을 임의 UUID로 바꾼다. 서버도 UUID 기반 파일명만 저장하며, OpenAI 전사 요청에서는 다시 임의 파일명을 사용한다. 기존 저장 파일의 이름은 소급 변경하지 않지만 이후 전사 요청의 파일명은 가린다. 확장자와 음성 바이트는 유지한다. 음성 속 발언과 파일 내부 메타데이터는 편집하지 않는다.

작업 결과의 `text_privacy`에는 처리 버전, 검사 여부, 종류별 개수와 가린 위치 수만 저장한다. 동일 이름이 여러 요청·필드에 반복되면 각각 센다. 이는 고유 인원 수나 유출 방지율이 아니다. 전사 검토·안내 화면에는 “AI 전송용 텍스트에서 식별정보 N곳 가림 · 요청별 사본 합계 · 원음·이미지 제외”를 표시한다. 설정 화면에서도 범위를 설명한다. 이전 작업에 이 처리 기록이 없으면 완료 배지를 소급 표시하지 않는다.

## 이번 구현에 포함하지 않는 것

- 로컬 음성 전사, 원음/실시간 스트림의 마스킹, 손글씨 이미지에서 식별정보를 먼저 가리는 처리.
- 일반 한국어 개체명 모델, 모든 개인정보 탐지, 식별정보를 제거한 결과의 완전 익명성 보장.
- 원음·브라우저 복구본·DB·로그의 자동 보관기한/삭제 정책, 계정별 실환자 접근권한 정책.
- OpenAI 계정의 ZDR 승인·설정, 처리위탁·국외이전 등 실서비스 도입 절차.
- 카카오 발송 문안을 익명으로 변경하는 기능. 카카오는 의료진이 별도로 승인한 문안을 사용한다.

현재 `store: false` 설정은 유지한다. 이 값만으로 모든 서비스와 모든 API 경로의 무보관을 보장하지 않는다. 데이터 학습·보관 조건은 [OpenAI 데이터 처리 문서](https://developers.openai.com/api/docs/guides/your-data)에서 실제 사용 모델·엔드포인트·계정 설정별로 확인한다.

## 검증

실제 개인정보나 외부 모델 호출 없이 합성 문자열과 모델 응답 대역을 사용한다. 요청 직전 입력에서 식별정보가 제거되는지, 임상 숫자가 유지되는지, 반환 근거가 원문으로 복원되어 검증되는지, 원문과 승인 기록이 유지되는지 검사한다. 한국어 전체 탐지 정확도를 측정한 결과로 해석하지 않는다.

검증 결과: 전송 경계·가림·복원 관련 신규 검사 10개를 포함한 단위 검사 97개, 서버 검사 39개, TypeScript와 프로덕션 빌드 통과. 격리 로컬 브라우저 검사 2개에서 가림 개수·보호 범위·원문 검토 표시와 파일명 치환의 브라우저 요청→서버 저장을 확인했다. 외부 AI 호출과 운영 데이터 변경 없이 검증했으며 실제 모델의 표식 유지율과 전체 한국어 탐지율은 이번 검사 대상이 아니다.

2026-10-09 합성 음성 실전사 검사에서 전체 전사에 `010-0000 -0000`처럼 공백과 하이픈이 함께 생기는 사례를 확인했다. 전화번호 구분자 조합을 허용하도록 보완하고 회귀 검사를 추가했다. 이름의 전사 오인식으로 등록 이름과 달라진 경우에는 여전히 탐지하지 못할 수 있다.
등록 이름 뒤의 `으로/로/이랑/랑` 조사도 가림 대상으로 포함하고 원문 복원 검사를 추가했다. 해당 가림·모델 요청 경계 검사 12개와 TypeScript 검사가 통과했다.


## v2 보완

명시적인 자기소개·의료진 소개와 생년월일 응답에 대한 로컬 규칙, 추가 의료진 이름 설정을 연결했다. 모델에 보내는 파일 사본은 음량 보정·메타데이터 제거를 적용하되 발화 내용은 가리지 않는다. 상세 범위와 검증은 [실제 동영상 전사 보완](asr-refinement.md)을 따른다.
