# 공개 파일 관리

## 공개 대상

코드·테스트·설치 안내·기여/보안/유지관리 문서를 기본으로 관리합니다. 데모용 데이터·이미지는 별도 출처와 권리 확인 대상입니다. 실제 진료 자료와 개발자의 작업 원본은 공개 대상이 아닙니다.

## 공개하지 않는 자료

- Codex 대화·세션 로그와 ZIP, 노션 원본과 내보내기
- 진료 녹음·영상·원문 전사, 환자 화면과 운영 DB·저장소 덤프
- 발표·대회 제출 자료, 외부 제품 스크린샷과 재배포 허락 없는 안내문
- 환경 파일, API 키·토큰·쿠키·인증 파일, 로컬 작업 디렉터리와 테스트 산출물

.gitignore는 새 파일의 유입을 막는 보조 수단입니다. 이미 추적된 파일은 자동으로 제외되지 않습니다. npm run check:public-files는 Git 추적 경로와 알려진 비밀값 패턴을 검사하지만 완전한 개인정보·비밀값·저작권 검사는 아닙니다. 이미지/오디오 내용, ZIP 내부, Git 과거 이력은 이 명령의 검사 대상이 아닙니다.

## 이번 정리와 남은 이력

기존 작업 사본의 원본은 로컬에 보존하고, 별도 작업 사본에서 공개 브랜치의 해당 자료를 제거합니다. 자료를 삭제한 커밋 이전의 main 이력과 원격 codex/emr-ui-redesign, codex/pencil-check-4ddeff5 브랜치는 그대로 남습니다. ‘현재 트리에서 제외’와 ‘공개 이력에서 제거’를 구분합니다.

완전한 이력 정리를 하려면 비공개 백업, 제거 경로 전체, 원격 브랜치·태그·PR, 협업자의 재복제, 기존 링크·배포 연결의 영향을 검토해야 합니다. 이후 소유자 승인 아래 이력을 재작성하고 명시한 원격 참조만 강제 갱신합니다. GitHub 캐시·PR 참조·포크·기존 복제본의 회수까지 보장할 수는 없습니다. 실제 키 노출이 확인되면 삭제와 별개로 폐기·재발급이 필요합니다.

가상 seed에서 비공개 자료를 가리키던 출처 ID와 직접 인용은 null로 가렸습니다. 근거가 공개 사본에서 검증 불가하다는 사실을 메타데이터에 남겼으며, 임의의 새 원문으로 출처를 바꾸지 않았습니다. 코드의 작은 차팅 용어 예시는 환자 발화 인용이 아닌 일반 용어로 교체했습니다. 가상 시나리오 전체의 재배포 권리 확인은 THIRD_PARTY_NOTICES.md의 차단 항목과 함께 해결합니다.
