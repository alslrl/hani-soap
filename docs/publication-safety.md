# 공개 파일과 Git 이력 관리

## 공개 범위

코드·테스트·기술 문서·가상 데모 자료와 출처별 이용조건을 보존한 외부 자산을 관리합니다. 실제 진료 자료와 개발자의 작업 원본은 공개 대상이 아닙니다. 공개 대상 자료의 조건은 [외부 자료 고지](../THIRD_PARTY_NOTICES.md)를 따릅니다.

## 제외하는 자료

- Codex 대화·세션 로그와 ZIP, 노션 원본과 내보내기
- 진료 녹음·영상·원문 전사, 실제 환자 화면과 운영 DB·저장소 덤프
- 발표·대회 제출 자료, 외부 제품 스크린샷과 재배포 허락 없는 안내문
- 환경 파일, API 키·토큰·쿠키·인증 파일, 로컬 데이터와 테스트 산출물
- 권한을 확정하지 못한 개인 PDF 유래 변증명 파생 파일과 지침 유래 명칭, 상위 권리 관계가 불명확한 복제 위치 설명

.gitignore는 새 파일의 유입을 막을 뿐 이미 추적된 파일과 과거 이력을 자동으로 지우지 않습니다. 공개 파일 검사도 Git 추적 경로와 알려진 비밀값 패턴을 검사하는 보조 수단입니다. 이미지 속 개인정보, 모든 비밀값, 임상 정확성이나 모든 권리 관계를 보증하지 않습니다.

## 2026-10-21 이력 정리

사용자가 커밋 주소 변경과 강제 갱신을 승인한 뒤, 원격 참조와 로컬 전체 이력을 비공개 vault에 백업하고 Git bundle 복원 가능성을 검증했습니다. 대상 원격 브랜치는 main, codex/emr-ui-redesign, codex/pencil-check-4ddeff5입니다. 당시 원격 태그와 PR 참조는 없었습니다.

별도 사본에서 제외 자료를 모든 대상 브랜치의 도달 가능한 Git 이력에서 제거했습니다. 혼합 출처 사전과 복제 위치 설명을 담던 파일은 과거 버전 전체를 먼저 제외하고, 현재 공개 조건에 맞춘 사본만 main의 새 커밋으로 다시 추가합니다. 일부 필드를 현재 파일에서만 지우고 원본 전체를 과거 이력에 남기는 방식과 구분합니다.

원격 갱신은 대상 참조 각각의 기존 SHA를 고정한 force-with-lease와 atomic push를 사용합니다. 작업 도중 다른 사람이 원격을 바꾸면 덮어쓰지 않고 중단하도록 합니다. 관련 원본·기존 SHA·변경 맵은 비공개 보관하며 공개 저장소에 새 백업 브랜치나 원본 bundle을 올리지 않습니다.

## 로컬 사본과 재유입 방지

이전 사본의 커밋을 새 이력에 그대로 merge하거나 강제 push하면 제거한 자료가 다시 공개될 수 있습니다. 새로 clone하는 방법이 가장 단순합니다. 필요한 미완료 변경은 검토 후 새 이력 위에 선별 적용하고 공개 검사를 다시 실행하세요.

.githooks/pre-push는 푸시할 참조의 도달 가능한 이력에 제외 파일 경로가 있으면 거절합니다. 제한 시간 안에 검사를 끝내지 못한 경우에도 통과로 취급하지 않습니다. 이 훅은 clone만으로 자동 설치되지 않습니다. 기존 훅·core.hooksPath 설정과의 충돌을 확인한 뒤 적용해야 하며, 그 자체가 완전한 비밀값·개인정보·저작권 검사는 아닙니다.

가상 seed에서 비공개 자료를 가리키던 출처 ID·직접 인용 50개는 null로 가렸습니다. 공개 사본에서 대조할 수 없다는 점을 [출처 설명](demo-data-provenance.md)에 남겼으며, 임의의 새 원문으로 바꾸지 않았습니다.

## GitHub 캐시와 외부 사본의 한계

브랜치 이력을 바꾸어도 GitHub의 캐시·기존 커밋 URL·PR 내부 참조·포크·기존 clone·이미 내려받은 파일이 즉시 삭제되거나 회수되는 것은 아닙니다. 필요한 경우 GitHub의 민감정보 제거 지원 절차와 외부 사본 보유자의 협조가 별도로 필요합니다. 실제 인증정보가 노출됐다면 이력 정리와 별개로 폐기·재발급해야 합니다. 검사 결과를 ‘인터넷에서 완전히 사라졌다’는 뜻으로 사용하지 않습니다.
