# 진료 분석·다중 입력 SOAP·맞춤 케어 검증

2026-10-09. 실제 환자 판단과 EMR 자동 연동은 데모 범위에 포함하지 않는다. 모든 AI 결과는 의료진 확인 전 초안이다.

통합 구현은 clinical-loop-plan.md를 따른다. 진료 분석 자동 hook, 인용 근거를 보존하는 미확인 답변 초안 저장, 단일 NRS/계단 입력, 확인 입력을 합친 SOAP, 날짜별 맥락을 반영한 케어를 연결했다. 후속 카카오 발송은 기존 승인 문안 경로를 유지한다.

검증 결과:

- TypeScript 및 production build 통과. 이중 전사와 iPad 도구의 최신 병행 커밋도 통합했다.
- 단위 171건·서버 47건 통과. 출처 인용, 개인정보 가림, 과거/현재·횟수/점수 구분, NRS 0, 편집/동시 입력 보호, 확인/중복/충돌, stale 승인 차단, 원문/승인 기록 보존을 포함한다.
- PostgreSQL 격리 검사 33건 통과. 기존 JSONB 저장 계약을 사용하며 새 테이블/seed 재설정은 없다.
- 관련 브라우저 10건 통과: 답변 초안/편집/원문, 늦게 도착한 AI 후보, 단일 NRS/계단 점수와 이동, 저장 중 편집 보호, 필수 질문 완료, 날짜별 케어 근거, 기존 연락 처리, 재로드/화면 배치.
- 실제 모델 합성 검사: 분석 3건, 맞춤 케어 2건, 다중 입력 SOAP 1건. 같은 승인 P에서도 지난 불편 보고와 실천 어려움에 따라 안내 방향이 달라졌다. SOAP에서 전사 0점·확인 시술·검토 필기가 각각 인용되었다. 모두 합성/격리 자료이며 새 카카오 실발송은 없다.
- 추가 opt-in 브라우저 케이스(카카오 provider fixture, live dual-ASR fixture)는 해당 전용 fixture 없이 통과로 계산하지 않았다. 기존 카카오 서버 fixture 검사는 서버 47건에 포함된다.

배포 뒤 PIN 인증·Supabase 상태·신규 분석 조회·진료/케어 페이지와 기존 카카오 연결을 읽기 전용으로 확인한다. 원문 전사·승인 SOAP·이미 승인한 안내 문안은 배포 전 기록과 대조한다. 운영 임상 입력 생성/수정과 새 메시지 발송은 이 검증에서 수행하지 않는다. 실물 iPad/Pencil/마이크 검증은 사용자가 진행 중이다. 대본/TTS 제작은 별도 세션이다.
