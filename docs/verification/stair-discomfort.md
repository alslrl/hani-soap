# 통증 옆 계단 오르기 불편 점수

2026-10-09. 통증 NRS가 있는 성인 발목 사례의 진료 화면에 ‘계단 오를 때 불편함’을 나란히 배치했다. 작은 화면에서는 두 패널을 세로로 쌓는다. 통합 진료 화면의 기존 통증 패널과 함께 표시한다.

별도 자체 기능 불편 척도로 0~10 정수를 입력·저장한다. 확인 안 된 값은 빈칸이며, 0은 유효한 기록이다. 기존 NRS와 계단 내려가기 기록을 복사하거나 같은 계열로 합치지 않는다. 저장 후 새로고침과 독립 경과 그래프를 지원한다. 배경 갱신은 입력 중인 점수를 덮어쓰지 않는다. 소아 야뇨 사례에는 이 패널을 추가하지 않는다.

저장 조건은 `STAIR_ASCENT_METRIC`에 정의했다.

- instrument: `APP_FUNCTION_DISCOMFORT`
- metric_key: `stair_ascent_discomfort`
- activity_key: `stairs_up`
- measurement_context: `stair_ascent_discomfort`
- body_region/laterality: `ankle`/`right`
- unit/scale: `score`, 0~10

기존 observation.save의 측정 조건 기반 series_key 생성·저장 경계를 사용한다. 미래 방문·다른 환자·다른 척도·미검토 관찰은 그래프에 섞지 않는다.

검증: TypeScript·production build, 별도 측정 계열 검사 2개, 격리 로컬 브라우저 검사 1개 통과. 브라우저에서는 나란한 배치, 미확인 빈칸, 0점 저장, NRS 불변, 재로드, 배경 갱신 중 입력 보존, 11/소수 거절, 경과 화면 한국어 이름, 좁은 화면 넘침 없음, 소아 패널 제외를 확인했다. UI 검증 점수는 합성 로컬 데이터이며 운영 기록에 저장하지 않았다.

전사에서 현재 오른쪽 발목의 계단 오르기 불편 점수가 명시되면 원문 인용과 함께 미확인 초안으로 채운다. 의료진 확인 저장은 분석 review API를 통해 원래 음성 근거와 수정 이력을 보존한다. 재진 기능 질문에는 같은 점수의 현재 값과 이동 버튼만 표시하고 중복 입력/재저장은 제외한다.

## 경과 보기 연결 수정

2026-10-09. 운영에서 계단 점수가 없는 상태로 ‘경과 보기’를 누르면 전체 경과 화면의 통증 그래프만 보여 계단 경과가 누락되는 것을 재현했다. 링크에 계단 측정 조건과 원래 방문 ID를 포함해 해당 방문까지의 확인된 계단 점수만 바로 표시하도록 수정했다. 저장된 점수가 없으면 계단 전용 빈 상태와 원래 진료실의 입력 위치로 돌아가는 링크를 제공한다. ‘전체 경과 보기’도 유지한다.

TypeScript·production build·관련 측정 단위 2건·실제 링크를 누르는 격리 브라우저 2건 통과. 빈 상태, 입력 위치 복귀, 저장한 0점, 새로고침, 전체 그래프 접근, 기존 NRS 보존을 검증했다. 검증 점수는 로컬에만 저장하며 운영 데이터에는 추가하지 않는다.

## 발표용 합성 과거 점수

사용자의 요청에 따라 10/2 8점, 10/4 6점, 10/7 4점의 계단 오르기 합성 과거 이력을 추가했다. origin=synthetic_history와 가상 점수라는 출처 인용을 저장한다. 오늘 점수는 자동 생성하지 않는다. 초기 seed에도 같은 자료를 포함하며 운영 상태에는 기존 입력을 보호하는 추가 스크립트를 사용했다. Supabase 상태와 정규화 observations 행에서 3건/8·6·4를 확인했다.
