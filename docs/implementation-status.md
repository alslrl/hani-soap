# 구현과 검증 상태

2026년 10월 9일 구현 기록입니다. 계획·실제 코드·외부 연결·기기 검증을 구분합니다.

## 구현된 기능

- PC 현황과 진료실: 환자 선택, 과거 승인 기록, SOAP 수정·새 버전 저장·승인, 별도 진료 시작·마침, 근거 대조, EMR 복사.
- PC 음성: 한 번 획득한 마이크 스트림의 전체 녹음과 WebRTC 전사, 입력 레벨, 녹음 이동 유지, 브라우저 청크 복구, 별도 음성 업로드.
- AI: 화자 분리 전사, 출처를 포함한 사전 후보 검색·보정 검토, 근거가 연결된 SOAP 초안, 승인 기록만 사용한 안내와 과거 기록 브리핑, 필기 텍스트 후보.
- iPad: 앞뒤 인체·부위 확대, 체크 패턴 인식, 부위별 경혈 팝업, 아시혈·압통점 설명, 시술별 독립 표시·필기, 초안과 시행 확인, PC 후보·시술 동기화.
- 재진·후속 관리: 12개 질문과 세부 답변, 직접 확인한 수치만 저장, 같은 조건별 경과 그래프, 안내 승인·모의 발송·응답, 불편 응답의 연락 작업과 처리 기록.
- 서버: PIN 세션, Origin 검사, 요청 상한, 버전 충돌 검사, 원문·승인 기록 보존, 로컬 및 Supabase 저장 어댑터, 비공개 음성 업로드, Vercel Workflow.

## 확인한 결과

- Next.js 프로덕션 빌드와 TypeScript 검사 통과.
- 로컬 PostgreSQL 격리 환경에서 migration·seed·정규 테이블·RLS·권한·버전 충돌·동시 저장·롤백·요청 상한 검사 통과.
- HaniSOAP 전용 Supabase 프로젝트 생성, migration 적용, 가상 환자 2명·방문 6회 seed 주입과 원격 DB lint 통과.
- 실제 음성 25초 구간으로 전사 모델 호출, SOAP Structured Output 및 인용 구간 검증, 사전 보정 모델 호출 통과.
- 실제 안내 초안 생성에서 승인 P의 근거 대조와 검토 전 초안 저장 확인.
- 실제 과거 기록 브리핑 생성과 문장별 승인 기록 인용 검증 통과.
- 브라우저 E2E 6개 통과: PIN·API 보호, 기록/진료 상태 분리, 안내·응답·연락, 시술 음성 문맥, 실제 체크·레이어 저장·PC 반영.
- 실제 WebRTC 연결에서 마이크 획득 1회, 확정 전사 3개, 전체 녹음 업로드와 Workflow SOAP 생성 확인. 검증에는 제공 음성의 가상 캡처를 사용했으며 사용자의 실제 마이크를 켜지 않았다.
- 전사 수기 검토 후 새 버전 기반 SOAP 재생성과 원문 보존, 이전 입력 SOAP의 승인 거절 확인.
- Vercel 배포 환경에서 PIN 보호·Supabase 조회와 실제 Workflow 브리핑 생성 후 DB 저장 완료 확인.

기하·AI·서버 단위 검사와 격리 PostgreSQL 검사도 통과했다. 손글씨 추출은 실제 호출 코드와 검토·revision 보호까지 구현했으며 아직 정확도 평가를 수행하지 않았다. 현재 손글씨 추출은 단일 요청이며 나머지 생성 작업의 durable Workflow와 구분한다.

## 인체 도해와 세로 작업면 검증

남성형 Z-Anatomy와 여성형 NIH/Human Reference Atlas의 실제 피부 모델을 각각 앞뒤 고정 PNG로 렌더링했다. 앱은 WebGL이나 3D 모델을 로딩하지 않는다. 여성 환자에게 여성형을 기본 표시하고 기존 필기는 이전 도해 기록에서 원본 그림·좌표로 보존한다. 세로 화면은 큰 인체와 상단 환자 정보, 하단 도구·기록·저장으로 구성한다.

클린 체크아웃에서 TypeScript·프로덕션 빌드·단위 검사 59개·서버 검사 21개가 통과했다. 이전 필기와 새 여성형 문서를 같은 방문에 별도 저장하는 PostgreSQL 검증도 수행했다. 세로 화면의 확대·체크·좌우·시트·회전·저장·재로드·PC 반영과 이전 기록 보존은 브라우저 기능 검사 2개를 통과했다. 별도 레이아웃 검사에서 834×1194·820×1180·1024×1366·1366×1024 모두 화면 넘침 없이 주요 조작에 접근할 수 있음을 확인했다. [도해 출처와 좌표 계약](reference/anatomy-render.md)을 따른다.

## 남은 외부·기기 확인

실물 iPad와 Apple Pencil 입력 품질, 실제 외장 마이크·진료실 소음 조건, 카카오 본인 발송은 OAuth 연결, 서버 토큰 암호화·갱신, 승인 문안 전송, 중복 방지, 만료 링크의 POST 응답으로 구현했습니다. 운영 계정의 인증과 실제 수신 결과는 아래 검증 기록 및 연결 상태로 구분합니다. EMR 구조화 쓰기는 포함하지 않습니다. 발표 PDF 제작은 별도 단계입니다.

카카오 본인 발송 운영 검증(2026-10-09): 실제 계정 연결 및 승인한 테스트 문안 1건 발송 성공, 중복 요청 차단, 사용자 휴대폰 수신 확인 완료. 자세한 동작과 검증 범위는 [카카오 연동](integrations-kakao.md)을 따른다.

화자 역할(2026-10-09): 전체 녹음·업로드 전사에서 전체 대화를 GPT-6.1 Sol로 검토해 의료진·환자·보호자·미확인 역할을 자동으로 채운다. 원래 화자 그룹을 함께 표시하고, 그룹 수정·개별 예외·예외 해제를 지원한다. 역할 수정은 새 전사 버전과 SOAP 재생성에 반영되며 기존 원문과 승인 기록을 보존한다. 통합 단위 테스트 87개, 서버 테스트 39개, 격리 PostgreSQL 검사 33개, 관련 브라우저 흐름 4개 통과. 실제 역할 추론은 합성 대화 3개로 검증했다.

## 텍스트 AI 전송용 식별정보 1차 가림

방문 차트의 환자·보호자 이름, 전화번호·이메일·주민번호 형식에 대한 서버 측 가림을 화자 역할 추정·용어 검토·SOAP·안내·브리핑 호출에 연결했다. 검토용 원문과 승인 기록은 유지하며, 보호 표식을 서버에서 복원한 뒤 원문 근거를 검증한다. 요청별 개수만 작업 결과와 화면에 표시한다. 새 음성 업로드와 전사 요청에는 임의 파일명을 사용한다. 원음·실시간 스트림·손글씨 이미지는 대상이 아니며, 완전 익명화·무보관을 의미하지 않는다. [상세 범위](text-privacy.md).

이 변경은 단위 검사 97개·서버 검사 39개·브라우저 검사 2개·TypeScript·프로덕션 빌드를 통과했다. 모델 요청은 합성 입력과 응답 대역으로 검사했다. 원음 전송이나 계정 보관 설정을 변경한 것으로 표시하지 않는다.

## 두 경로 전사

전체 음성에서 gpt-transcribe 본문과 gpt-4o-transcribe-diarize 화자·시간 결과를 병렬로 얻고, 본문 원문을 보존하며 화자에 대응시킨다. 모델별 원본과 결합본을 별도 revision으로 저장한다. 불확실한 화자 대응은 미확인으로 남기며 표현 차이와 두 원본을 검토 화면에 표시한다. 실제 64초 합성 음성의 격리 실행에서 8개 발화·이름·통증 수치·발 높이기 안내와 원본/승인 기록 보존을 확인했다. [설계와 검증 한계](dual-transcription.md).

구현 시 단위 검사 117개·서버 검사 39개가 통과했다. 최신 UI 병합 후 관련 단위 검사 12개·브라우저 검사 3개·TypeScript·프로덕션 빌드를 확인했다. 실제 로컬 브라우저에서 역할 수정의 새 revision 저장과 새 ID 기반 SOAP 요청까지 검증했으며 이 기능의 운영 배포는 별도다.

## 진료 분석·다중 입력 SOAP·맞춤 케어 통합

- 전사 후 답변·현재 수치·직접 표현 후보를 자동 분석한다. 실제 답변은 인용과 함께 미확인 초안으로 채우고, 기존 의료진 입력과 편집 중인 값은 보존한다. 통증 NRS/계단 오르기 점수는 진료 화면의 단일 입력에서 확인하며 재진 질문에는 현재 값과 이동 링크를 표시한다.
- SOAP에 같은 방문의 시행 확인 시술·검토 필기·확인 답변/측정을 추가하고 출처를 보존한다. 생성/승인 시 입력이 달라지면 갱신을 요구한다.
- 승인 계획과 날짜별 지난 응답·확인된 걱정·실천 어려움을 바탕으로 케어 방향/이유/근거를 제시한다. 문안은 의료진 검토 후 승인하고 기존 승인 문안은 보존한다.
- 계획은 clinical-loop-plan.md, 상세 검증은 verification/clinical-loop.md에 정리했다. 실물 기기 검증은 사용자가 진행 중이며 환자 대본/TTS 리허설은 별도 작업이다.
